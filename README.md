## 📌 Архітектура та підхід

Це потоковий парсер HTML без використання DOMParser або innerHTML (відповідно до вимог завдання).

Я використав:
- **посимвольний перебір строки (O(n))**
- **stack-based дерево (LIFO стек) для вкладеності**
- **state machine підхід (TAG / TEXT / RAW mode)**

Основні режими:
- **TAG MODE** — обробка тегів `<div>`, `<p>` тощо
- **TEXT MODE** — накопичення тексту між тегами
- **RAW MODE** — спеціальна обробка `<script>` та `<style>`

## ⚙️ Обробка edge cases

### 🔹 Самозакриваючі теги
Підтримуються:
- `<br>`
- `<img>`
- `<input>`
- та інші з whitelist (`SELF_CLOSING`)

➡️ Вони не додаються в stack і не мають children.

### 🔹 Вкладені структури
- Використовується стек (`stack`)
- Кожен новий тег додається в children поточного вузла
- Закриття тегу відбувається через пошук у стеку (`closeTag`)

➡️ Це забезпечує коректну побудову дерева будь-якої глибини.

### 🔹 `<script>` та `<style>`
- Переводяться в **RAW MODE**
- Весь внутрішній текст не парситься як HTML
- Зберігається як `content`

➡️ Це захищає від “поламаних” тегів всередині JS/CSS.

### 🔹 Невалідний або битий HTML
- Парсер не падає
- Використовується fallback-логіка:
  - пропуск некоректних тегів
  - захист стеку (root завжди існує)
  - обробка відсутніх `>` через break

➡️ Гарантовано стабільний output навіть при поганому input.

### 🔹 Атрибути
Підтримуються:
- `key="value"`
- `key='value'`
- boolean атрибути (`disabled`, `checked`)

➡️ Якщо значення відсутнє → встановлюється `true`

## 🚀 Як запустити

## 💡 Ключова ідея
Парсер побудований як **легкий streaming HTML engine**, який:
- не використовує DOM
- працює за O(n)
- витримує некоректний HTML
- будує JSON AST дерево
